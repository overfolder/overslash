| [mcp-elicitation-approvals.md](mcp-elicitation-approvals.md) | Adopted (Flow A, default-on) | Approvals surface as `elicitation/create` for clients that declare the capability. Safe because an *unanswered* dialog is not a denial: only `decline` denies, everything else retires the row and returns the byte-identical `pending_approval` envelope, so URL-reject is the substrate rather than the alternative. Re-prompting is bounded by a per-agent post-cancel cooldown. Storage records only the explicit opt-out (migration 123), because capabilities are always unknown at consent time and a capability-gated default would never fire. Flow B (tasks) still rejected — not declared by any client. URL mode is client-side available: Codex 0.157.0 offers it on `2025-06-18` already, Claude Code 2.1.282 only on `2026-07-28` — which `/mcp` now also speaks (D-NEXT), approval dialogs there being multi round-trip requests (`input_required` + signed `requestState`). Codex works interactively; **headless** `codex exec` auto-`decline`s elicitations (openai/codex#45621), and D95 reads a decline as a real denial — a narrow hazard Overslash cannot detect, since the two surfaces are identical at `initialize`. Probe at `test-mcp-elicitation/` — note it cannot reach `2026-07-28`, so its URL-mode result is not falsifiable. |

| [layered-service-templates.md](layered-service-templates.md) | Implemented | Unifies forks and catalog overlays into one **layer** primitive: a `service_templates` row with `extends` (NULL=standalone full doc, set=derived delta over a base) resolved by a recursive **fold** (`resolve(layer)=apply(delta, resolve(extends))`). Masks (allowlist/denylist, clamp-up risk, disclose, relabel) are monotonic/order-independent so containment is structural; extensions (add actions/hosts, no auth, no rebinding) are bounded; `extends` is a **live pointer** (tracks upstream). Authority is namespace-based (`user_template_policy: none\|restrictive\|full`); classifier + scope constraints deferred but reserved. Supersedes the org-catalog-overlay draft. |
| [mcp-enrollment-org-scoping.md](mcp-enrollment-org-scoping.md) | Implemented | Guarantee that `<org>.{app,api}.overslash.com/mcp` onboards agents **only** into `<org>`. Today `pending.org_id` comes from the session, not the subdomain, and DCR clients are org-global — an authenticated cross-org session can divert enrollment. Fix: derive enrollment org from `ctx`, re-auth on session/subdomain mismatch, scope the fast-path binding by org, and stamp `org_id` on `oauth_mcp_clients`. |
| [email-integration.md](email-integration.md) | Implemented (Inline core) | Email send + on-demand read across the standard-IMAP long tail via **overfwd**, a separate MIT OSS Mailbox Gateway (`overspiral/overfwd`) presenting a REST facade over IMAP/SMTP. No native mail transport in core; Overslash uses Inline (credential-free) mode via `services/email.yaml`. Gmail on REST, Graph a later track; **Yahoo rides the gateway** (no REST API exists, app-password IMAP works — see D37); own-inbox/real-time-inbound deferred. Core changes shipped: `SecretRef` base64 encode (`x-overslash-encode`) + generic multi-injection (`x-overslash-secret_source: instance\|org`) + per-instance `url` override on HTTP Mode C. See D28. |
| [credential-templates.md](credential-templates.md) | Implemented | Credential **slots** (`components.x-overslash-secrets`) declared once and composed into injections by a jq template (`x-overslash-template`) — one secret may feed several headers, one header may join several secrets (`email.yaml`'s `user:pass`). Removes `x-overslash-prefix`/`-encode`. Which slots an expression reads is resolved statically from jaq's AST at compile time, so the send path decrypts exactly those; dynamic key access is rejected. Covers the two evaluator hazards: jq errors quote secrets, and `"user" + null` silently truncates a credential. See D35. |
| [event-stream.md](event-stream.md) | Implemented | `GET /v1/events/stream` — SSE with a fixed 30s connection ceiling and `Last-Event-ID` resume (SPEC §10). Durable `events` table whose `BIGSERIAL id` is the cursor; an `AFTER INSERT` trigger `pg_notify`s just that id and each replica's `PgListener` republishes onto a local `tokio::broadcast`, so no Redis and one delivery path. Visibility is a frozen `audience uuid[]` mirroring `mine`/`assigned`/`actionable` — deliberately narrower than the un-gated `GET /v1/approvals`. One `services::events::emit` seam feeds the stream *and* webhooks (replacing all 8 `dispatch()` sites); adds `secret_request.*`. Dashboard drops to stream-driven updates with polling as fallback. See D45. |
| [widget-sdk.md](widget-sdk.md) | Approved — in progress | `@overslash/sdk` — the JS SDK third parties embed to surface approvals, secret requests and connects in their own UI. One package at `sdk/`, zero runtime deps, subpath exports: headless client + controllers (ports of `resolution.svelte.ts`, `format.ts`, `oauth-connect.ts`) and custom elements themed by `--overslash-*` custom properties and `::part`, no framework bindings. Three auth modes — `apiKey` (+`X-Overslash-As`), host-proxy `transport` (works today), and short-lived `aud=widget` tokens (backend follow-up, specified here). Realtime is a fetch-based SSE parser over D45's stream (`EventSource` can't set `Authorization`; owning the cursor makes reconnect lossless) with polling as fallback. See D46–D50. |
| [generic-pagination.md](generic-pagination.md) | Implemented | One vocabulary for paging over the eight spellings of page size and six of continuation the shipped corpus carries: `x-overslash-pagination` names the parameter that bounds a page (seeding its own `default:` so `apply_defaults` — the mechanism that already existed — puts it on the wire) and how to reach the next one (`cursor` / `offset` / `page` / `link` — a whole next URL, from the RFC 8288 header or a dotted body path). A paged result carries a uniform `_pagination.next` holding the *difference* between the call just made and the next one, in the action's own parameter names. Read from the raw body and headers, upstream of both the jq filter and the compact render. The gateway never follows a page. Swept onto the whole corpus, with a gate that keeps it swept, and extended to the MCP runtime by unwrapping the result envelope. Builds on D74. |
| [service-setup-links.md](service-setup-links.md) | Approved — implemented | Service setup links and the credential probe (D83). `x-overslash-test` nominates one read action per template as its credential probe; `POST /v1/services/{id}/test` runs it through the ordinary call path — no approval bypass — and returns a verdict carrying status, latency and the upstream error but never the body. `create_service` auto-mints a signed setup link for every unbound per-instance slot (`setup.setup_url`), the twin of the OAuth `connect.auth_url` it already returns; migration 118 adds `service_instance_id` + `credential_key` to `secret_requests` so fulfilling one writes the vault secret *and* binds the slot. Records why the columns are additive rather than the `credential_requests` table `agent-credential-provisioning.md` proposes, and why the public Test button requires a session. Extended by D86: the verdict now *gates* the instance rather than describing it — a setup-created service is written `status: pending_setup`, uncallable and invisible to search, until `POST /v1/services/{id}/activate` gets a green verdict; setup links always require a session, because an anonymous fulfilment can never produce one; and unverified instances are swept after ~24h. |
